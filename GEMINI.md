
# Project Overview: doc-to-form

This project aims to convert legal document templates into interactive web forms. Initially, it converted `.docx` files into static HTML forms. It has since evolved to support dynamic rendering of forms from structured JSON data, allowing for easier management, categorization, and expansion of templates.

## Key Directories and Files

-   **`/forms`**: Contains the original static HTML forms generated from `.docx` files. This directory is part of the legacy static application.
-   **`/converted`**: Likely contains `.docx` files that were processed into HTML forms.
-   **`/downloaded`**: Placeholder for downloaded source documents.
-   **`/spec`**: Contains specification files that define how fields are detected and how templates are structured.
    -   `field-spec.v1.json`: Defines field types and detection rules.
    -   `templates.manifest.json`: The original manifest for the static HTML forms.
-   **`/static`**: Contains static assets like CSS and JavaScript.
    -   `style.css`: Styling for both static and dynamic forms.
    -   `app.js`: The core JavaScript logic for the new dynamic application.
-   **`/templates`**: This is the central directory for JSON templates.
    -   `templates/manifest.json`: The primary manifest file for the dynamic application, listing all available JSON templates with their metadata.
    -   `templates/original_html/`: Contains JSON templates that were converted from the original static HTML forms.
    -   `templates_scraped_and_generated/`: Contains JSON templates that were either generated from scratch by the LLM or scraped from external websites. These are further organized into subdirectories by category (e.g., `contracts`, `declarations`).
-   **`index.html`**: The entry point for the **original static application**. It lists links to the HTML forms in the `/forms` directory.
-   **`app.html`**: The entry point for the **new dynamic application**. It loads templates from `templates/manifest.json` and renders them using `static/app.js`.
-   **`html_to_json.py`**: A Python script used to convert the original static HTML forms into the initial JSON format.
-   **`organize_templates.py`**: A Python script used to reorganize the JSON templates into `original_html/` and `scraped_and_generated/` directories and update the manifest.
-   **`scrape_bulletin.py`**: A Python script used to scrape legal document templates from `bulletinofficiel.com` and convert them directly into JSON templates.

## Changes Made by the LLM

The project has undergone a significant architectural shift:

1.  **Dynamic Application (`app.html`)**: A new single-page application has been introduced, capable of dynamically loading and rendering forms from JSON data.
2.  **JSON Template System**: Forms are now defined in a structured JSON format, stored in the `/templates` directory.
3.  **Template Categorization and Separation**:
    *   Templates are now organized into distinct directories based on their origin:
        *   `templates/original_html/`: For templates derived from the initial HTML conversions.
        *   `templates_scraped_and_generated/`: For templates generated by the LLM or scraped from external sources, further categorized into subfolders (e.g., `contracts`, `declarations`).
    *   The `templates/manifest.json` file tracks all templates, including their `file` path (relative to `templates/`) and a `source` field (`original_html_conversion` or `new_generated`) to indicate their origin.
4.  **Enhanced Frontend Logic (`static/app.js`)**: The JavaScript application has been updated to:
    *   Load templates from the new categorized directory structure.
    *   Display the source of each template in the list view for easy identification.
5.  **Scraping Capability**: A Python script (`scrape_bulletin.py`) was developed to automatically extract templates from external websites and convert them into the project's JSON format.
6.  **Template Expansion**: Over 100 new templates have been generated/scraped and integrated into the dynamic application.

## How Templates Work

-   Each form is represented by a JSON file (e.g., `loan-agreement.json`).
-   This JSON file defines:
    -   `id`: A unique identifier for the template.
    -   `title`: The display title of the template.
    -   `fields`: An array of objects, each describing an input field (`id`, `type`, `label`).
    -   `structure`: An array of objects representing the document's layout, containing paragraphs (`type: "paragraph"`) with mixed text and field references (`type: "text"`, `type: "field"`), and line breaks (`type: "break"`).
-   `static/app.js` reads `templates/manifest.json` to get a list of templates. When a template is selected, it fetches the corresponding JSON file and dynamically constructs the HTML form based on its `structure` and `fields` definitions.

## LLM Instructions/Checklist

When interacting with this project, please consider the following:

1.  **Understand the Dual Application Structure**:
    *   The **static application** (`index.html` -> `/forms/*.html`) remains untouched.
    *   The **dynamic application** (`app.html` -> `static/app.js` -> `/templates/**/*.json`) is the primary focus for new template development and management.
2.  **Template Identification**:
    *   Refer to `templates/manifest.json` for the authoritative list of templates for the dynamic app.
    *   The `source` field in `templates/manifest.json` (e.g., `"original_html_conversion"`, `"new_generated"`) indicates the template's origin.
3.  **Adding New Templates**:
    *   Create new JSON template files directly in `templates_scraped_and_generated/<category>/<your-template-id>.json`.
    *   Ensure the JSON structure adheres to the `id`, `title`, `fields`, `structure` format.
    *   **Crucially**, update `templates/manifest.json` by adding a new entry for your template, setting `source: "new_generated"` and ensuring the `file` path is correct (e.g., `"file": "scraped_and_generated/contracts/your-template-id.json"`).
4.  **Modifying Existing Templates**:
    *   Locate the JSON file in either `templates/original_html/` or `templates_scraped_and_generated/<category>/`.
    *   Edit the JSON content directly.
    *   If the `id`, `title`, or `category` changes, update the corresponding entry in `templates/manifest.json`.
5.  **Reviewing/Removing Templates**:
    *   To review templates by source, use the `source` field in `templates/manifest.json`.
    *   To remove a template:
        1.  Delete its entry from `templates/manifest.json`.
        2.  Delete the corresponding JSON file from its directory (`templates/original_html/` or `templates_scraped_and_generated/<category>/`).
6.  **Legal Disclaimer**: Any templates generated or scraped by an LLM are for structural demonstration only. **They are not legal advice and must be reviewed and validated by a qualified legal professional before actual use.**
7.  **Scraping**: If further scraping is required, the `scrape_bulletin.py` script (if still present) can be adapted, or a new script can be created following similar principles. Be mindful of `robots.txt` and website terms of service.
